# TaurusDB 文档召回试测集

试测集使用 40 个华为云帮助中心页面，包含 TaurusDB 与 TaurusDB 标准版。覆盖参数、备份恢复、读写分离、只读节点、日志审计、SSL 和版本管理。其中 29 页有标注证据，另外 11 页提供相关干扰。

- `sources.json` 保存页面地址、文档 ID、产品版本范围和站点。
- `questions.jsonl` 包含 40 道题。精确定位、语义改写、版本或环境混淆各 8 道，跨文档题 10 道，无答案题 6 道。跨文档题中有 4 道需要三篇文档。
- `updates.jsonl` 包含 5 组虚构测试环境的原位更新样本。每组有一个稳定文档 ID、两个版本、同一查询和新旧证据。
- `build_corpus.py` 从来源构建 Markdown 语料。只有所有标注都能定位到构建后的原文时，才写出数据集。

## 生成同一份入库语料

在能访问华为云帮助中心的环境中运行。Python 3.10 及以上。

```sh
python -m pip install lxml
python build_corpus.py --check-labels
python build_corpus.py --output taurusdb-pilot-corpus
```

也可以使用 `--html-dir saved-html`，文件名为 `<document_id>.html`。输出包括 `corpus/`、与上一轮结构兼容的 `questions.jsonl`、`updates.jsonl` 及文档哈希清单。两边复用同一次构建结果。网页变更导致证据定位失败时，按报出的题目和文档 ID 复核原文。

## 接入上一轮对比

把构建后的 `corpus/` 和 `questions.jsonl` 放到混合检索跑测脚本读取的同一题集目录。给两边建独立的试测知识库，使用相同查询和正文预算，保留各自的混合检索与模型重排。

- 证据召回按 2,000 正文 Token 计算，并记录 256 和 512 的结果。
- 证据 Hit@5 检查原生顺序前 5 条结果中的正文。
- 跨文档完整命中单独统计 10 题。一个文档包含多条事实时，仍按不同来源文档检查完整性。
- 无答案题单独统计返回候选与错误证据。无答案题的预期范围是本语料。
- 更新用例使用独立测试库，先导入 V1 并验证可召回，再用同一文档 ID 更新到 V2。以提交更新为起点，分别记录首次命中新证据和旧证据消失的时间。用相同轮询间隔和正文预算。

## 核验状态

问题按公开文档人工编写，标注证据保留来源。部分单证据题的证据也用于跨文档组合，这套题定位为试测。正式题集应独立留出文档族，并人工复核同一事实是否还有其他有效来源。

当前环境的直接 HTTP 请求拿到站点不可用响应。已完成来源与证据抽核、数据结构校验、离线 HTML 构建测试。真实网页批量下载、原文入库和产品跑分待在可访问官网的环境执行。
